# txtx 项目流程梳理

本文记录当前代码库里“真实在运行”的主流程，方便后续继续收敛架构和补功能。

## 1. 项目定位

`txtx` 是一个本地单机小说下载工具。

用户流程目标很简单：

1. 配好站点和规则
2. 发起扫描或单本下载
3. 在任务里确认书单、观察进度、处理失败项
4. 把结果保存到本地目录

## 2. 技术结构

### 前端

- `src/` 下是 React + Vite 前端
- 路由入口在 `src/router.tsx`
- 全局布局在 `src/layouts/RootLayout.tsx`
- 状态主要分两套：
  - `configStore` / `aiStore`：配置类状态
  - `taskStore`：任务主流程
  - `downloadStore`：旧下载流，仍有部分展示组件依赖

### 后端

- `src-tauri/` 下是 Rust + Tauri
- Tauri 命令入口主要在 `src-tauri/src/lib.rs`
- 下载、扫描、历史、任务持久化都在 Rust 侧完成

## 3. 页面职责

### 首次运行

- `RootLayout` 启动时调用 `apiCheckFirstRun`
- 如果是首次运行，展示 `SetupWizard`
- 用户完成目录选择后，写入配置并进入正常页面

### 首页 `DownloadPage`

当前首页已经从“下载主控制台”逐步收敛成“任务发起台”。

主要职责：

- 选择扫描日期范围
- 选择扫描站点
- 发起扫描任务
- 发起单本下载任务
- 批量导入 URL 并创建任务
- 提供进入任务管理的快捷入口
- 当已有任务在运行时，明确引导用户去任务管理查看和操作

不再建议把首页当作完整下载主流程的唯一承载页。

### 任务管理 `TaskManagerPage`

这是当前推荐的主流程页面。

主要职责：

- 展示任务列表
- 查看扫描中 / 下载中 / 已完成 / 已失败任务
- 在扫描完成后展示候选书单
- 确认下载选中项
- 查看日志
- 重试、暂停、取消、删除任务

### 规则管理 `RulesPage`

负责维护站点规则，使用向导编辑：

- 站点域名
- 列表页规则
- 章节页规则
- 内容 XPath
- 编码覆盖等配置

### 其他页面

- `WebsitesPage`：网站配置和站点启停
- `SettingsPage`：通用配置、网络、并发、AI、路径等
- `FilterPage`：过滤、广告清理、黑名单
- `HistoryPage`：下载历史
- `HealthPage`：站点健康检查
- `ConverterPage`：文本转换

## 4. 当前主流程

### A. 扫描下载流程

1. 用户在首页选择时间范围和站点
2. 首页调用 `taskStore.createScanTask`
3. 前端跳转到任务管理页
4. Rust 后端开始扫描，持续发出 `task_event`
5. 扫描完成后任务进入 `preview`
6. 用户在任务详情里选择要下载的书
7. 前端调用 `confirm_task_download`
8. 后端继续执行下载
9. 下载完成后任务状态变成 `done`

### B. 单本下载流程

1. 用户在首页输入 URL
2. 前端创建 `single_download` 任务
3. 用户在任务管理页查看进度
4. 任务完成或失败后可以重试

### C. 批量导入流程

1. 用户在首页导入多个 URL
2. 前端逐条创建单本下载任务
3. 用户去任务管理统一查看结果

## 5. 前后端数据流

### 配置流

- 前端通过 `configStore` 调 `apiLoadConfig` / `apiSaveConfig`
- Rust 侧通过 `config_db` 持久化

### 任务流

- 前端通过 `taskStore` 创建任务
- Rust 侧生成 `TaskRecord`
- 扫描 / 下载过程中不断发出 `task_event`
- 前端监听事件并更新任务列表和详情
- 完成后的任务落到 SQLite

### 旧下载流

旧流仍然存在：

- `downloadStore`
- `downloadEventHandler`
- 一部分旧扫描/下载展示组件

这套流还没有彻底移除，但首页的新入口已经优先走任务体系，
而且运行态已经不再把首页当成主控制界面。

## 6. 目前已经完成的收敛

- 首页单本下载改为创建任务
- 首页批量导入改为创建任务
- 首页扫描入口改为创建扫描任务并跳转任务管理
- 单本任务保存 `source_url`，重试可闭环
- 任务管理已经可以承接扫描预览与确认下载
- 命令面板中的扫描入口已改为创建任务
- 历史页中的重新下载已改为创建任务并跳转任务管理
- 首页未完成队列提示已改为引导用户前往任务管理，而不是直接回到旧批量下载流
- 旧结果页中的“再次扫描”已改为返回任务发起台/任务管理，不再直接拉起旧扫描流
- 旧预览页中的“重新扫描”也已改为回到任务发起台，不再直接拉起旧扫描流
- 组件层面已经没有页面主动调用旧 `startScan()`，旧扫描流目前主要只剩兼容层代码

## 7. 仍需继续完善的点

### 高优先级

- 继续减少首页对 `downloadStore` 的依赖
- 把旧扫描预览组件改造成任务页可复用组件，或逐步退场
- 统一“暂停/恢复/停止”在首页与任务页的行为语义

### 中优先级

- 为任务流补前端编译和交互验证
- 给任务创建失败补更明确的用户提示
- 梳理任务列表与首页状态提示之间的关系

### 低优先级

- 清理已不再走主路径的旧文案
- 统一“下载控制台 / 任务管理 / 扫描预览”等命名

## 8. 当前建议

后续开发建议默认遵循下面这条原则：

“首页负责发起，任务页负责执行与查看，Rust 后端负责真实状态与持久化。”

只要继续沿这个方向推进，项目流程会越来越清晰，状态分裂也会逐步消失。
